C4 - Analisis de CORS/PNA con Ngrok

Proyecto: ecommerce-trini

C1 - Contexto del Sistema

flowchart LR U[Usuario en navegador] NG[Ngrok Edge publico HTTPS] FE[Frontend Vite] BE1[Backend Ecommerce API local puerto 3000] BE2[Backend Admin API local puerto 3001] U -->|HTTPS| NG NG -->|tunel| FE FE -->|HTTP| BE1 FE -->|HTTP| BE2
El navegador entra por ngrok al frontend; luego el frontend reenvia a las APIs locales.

C2 - Contenedores: Caso A (Frontend en Docker, APIs en host local)

flowchart TB subgraph Internet U[Browser usuario] NGEdge[Ngrok dominio publico] end subgraph DockerCompose frontend-ecommerce FEC[Contenedor Frontend Vite puerto 5173] NGC[Contenedor Ngrok] end subgraph Host Windows BE1[API Ecommerce localhost 3000] BE2[API Admin localhost 3001] end U -->|HTTPS| NGEdge NGEdge --> NGC NGC -->|frontend:5173| FEC FEC -->|proxy /api/v1 -> host.docker.internal:3000| BE1 FEC -->|proxy /api/v1/admin -> host.docker.internal:3001| BE2
  • Si el proxy usa localhost dentro del contenedor, apunta al contenedor y no al host.
  • Ese error de red termina como 502 Bad Gateway desde ngrok.

C2 - Contenedores: Caso B (Frontend sin Docker, APIs en host local)

flowchart TB subgraph Host Windows FEH[Proceso Vite local puerto 5173] BE1[API Ecommerce localhost 3000] BE2[API Admin localhost 3001] NGL[Ngrok local] end U[Browser usuario] -->|HTTPS| NGL NGL -->|tunel a localhost:5173| FEH FEH -->|proxy /api/v1 -> localhost:3000| BE1 FEH -->|proxy /api/v1/admin -> localhost:3001| BE2
  • Aqui localhost si es el host real, por eso funciona.
  • Se mantiene mismo origen para el browser y se evita CORS/PNA.
